# n8n-MCP authentication

The optional `n8n-mcp` Compose profile requires two different credentials:

- `N8N_MCP_TOKEN` authenticates inbound MCP HTTP clients and may be generated by
  `scripts/03_generate_secrets.sh`.
- `N8N_API_KEY` authenticates the MCP server to n8n's public API. Copy a public
  API JWT issued in n8n under Settings -> API. It is never generated by this
  repository.
- `N8N_URL` is the HTTPS base URL for that n8n public API check.

When `n8n-mcp` is selected, the generator and service-selection wizard perform
cheap fail-closed checks for JWT syntax, `public-api` audience, and any expiry
claim. The service runner then makes a bounded HTTPS request to
`N8N_URL/api/v1/workflows?limit=1` with `X-N8N-API-KEY`; only a 2xx status
passes. This live API response is authoritative for signature, issuer,
revocation, and server-side expiry checks. The checks do not print the
supplied value. A blank `N8N_API_KEY` remains valid when `n8n-mcp` is not
selected.

If validation fails, set the value in the runtime `.env` from n8n's API-key
settings and rerun the wizard. Never paste either credential into logs,
documentation, or source control. Compose keeps the two values mapped to
separate environment variables in the `n8n-mcp` service.

The Compose healthcheck repeats the missing-key and public-API status guard, so
direct `docker compose --profile n8n-mcp up` activation cannot report a healthy
MCP service with a missing, forged, or rejected API key.
